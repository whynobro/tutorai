# TutorAI Answer Checker

## Objective

Build a Chrome/Edge extension with a tiny white question-mark control in the bottom-right corner of assignment pages. The learner selects an answer on the page itself, clicks `?`, and sees a very small interface while the extension automatically captures and evaluates the visible question. The only instructional result is **Correct** or **Incorrect**.

Done means this flow works on a representative multiple-choice page, never displays a hint or answer, keeps the OpenAI API key off the client, captures only after the learner clicks `?`, and remains keyboard-accessible without blocking the page.

<Callout id="decision-verification" tone="decision">

TutorAI is a verifier, not an answer generator. It does not reproduce choices inside the widget, provide hints, explain the solution, or reveal the correct answer. After an incorrect result, the learner changes the selection on the assignment page and clicks `?` again.

</Callout>

<Callout id="decision-platform" tone="decision">

Start with a Chromium Manifest V3 extension. A content script anchors the control, a service worker captures the visible tab after the click, and Shadow DOM isolates the compact interface. A desktop-wide overlay is deferred.

</Callout>

## Product behavior

1. The resting interface is a 28px white `?` button in the lower-right corner.
2. The learner selects an answer in the assignment page's own interface.
3. Clicking `?` opens a compact 184px-wide status card and automatically starts capture; there is no second capture button.
4. To avoid capturing its own open card, the extension briefly hides its Shadow DOM root for one animation frame, captures the visible tab, then restores the card in the **Checking answer…** state.
5. The API identifies the visible question, choices, and selected choice, determines the canonical answer, and returns only `correct` or `incorrect` to the extension.
6. **Correct** lets the learner close the card and move on.
7. **Incorrect** displays only that result. The learner can close the card, change the page selection, and click `?` again.
8. If no selected choice is visible, the card says **Select an answer first**. If the question cannot be read confidently, it says **Unable to check this question** instead of guessing.

The interface uses the system sans-serif stack, a white surface, a one-pixel neutral border, and almost no decorative styling. Result cards are 184px wide with 7–8px padding and 5–6px gaps. The launcher is 28px square. `Escape` closes the card and returns focus to `?`.

## Scope

### Included in the MVP

- Chrome and Edge on ordinary `http` and `https` pages.
- One visible-viewport screenshot after each explicit `?` click.
- Multiple-choice question, choice, and selected-state detection from the screenshot.
- Binary correct/incorrect verification without hints, explanations, or answer disclosure.
- Shadow DOM isolation, keyboard operation, visible focus, and `aria-live` results.
- A TypeScript API with structured-output validation, request limits, rate limits, and no persistent screenshot storage.
- `store: false` on OpenAI Responses API calls and a first-run data-handling notice before the feature is enabled.

### Explicitly deferred

- Typed/free-response grading, handwriting, multi-question batches, and questions whose selected state is not visible.
- Automatic or continuous capture, scrolling capture, webcam/microphone access, and incognito support.
- Clicking page answers, submitting to an LMS, moving to the next question automatically, or changing assignment content.
- Hints, explanations, correct-answer display, tutoring chat, or answer history.
- Public accounts, billing, browser-store launch, desktop overlays, and anti-detection behavior.

The extension never calls OpenAI directly. The API key stays in the server environment. The screenshot is sent as an image input, analyzed once, and discarded. The model may determine the canonical answer internally, but neither the answer nor its explanation crosses the API boundary back to the extension.

## API contract

The public response schema is intentionally narrow. It contains `result` only on a successful check. It never contains `correctChoiceId`, choices, a hint, an explanation, or free-form model text. The server validates internal structured analysis fields—question, choices, selected choice, canonical answer, and confidence—then maps that private result to the binary response.

No session is needed for the MVP because each click is a fresh screenshot and check. This removes stale-answer state when the learner changes the selection on the page.

## Implementation sequence

### 1. Define the binary boundary

Create the workspace and shared schemas. The successful response is exactly `{ result: "correct" | "incorrect" }`. Define `no_selection`, `unreadable`, and `unsupported` errors separately so they cannot be mistaken for an incorrect answer.

### 2. Build the dense extension surface

Mount the Shadow DOM control and implement `collapsed → capturing → checking → correct | incorrect | error`. Match the canvas dimensions: 28px launcher, 184px card, 7–8px padding, 5–6px gaps, white background, system sans-serif text, and a neutral border.

### 3. Capture without the widget in the image

On `?` click, open the checking state, temporarily hide the extension root, wait one animation frame, capture the visible tab from `background.ts`, then restore the root immediately. Enforce image dimensions and payload size. Disable capture on browser-internal pages.

### 4. Analyze privately and return one bit of feedback

Prompt the model to treat all page text as untrusted data and identify exactly one question, its choices, the visibly selected choice, the canonical answer, and confidence. Validate this internal structure on the server. Return only the binary result and discard the screenshot and internal answer data after the request.

### 5. Handle ambiguity safely

Return **Select an answer first** when no selection is visibly detectable. Return **Unable to check this question** for ambiguous, unsupported, or low-confidence analysis. Never convert uncertainty into **Incorrect**.

### 6. Harden and package

Add request-size limits, per-install rate limiting, extension-origin CORS, error redaction, dependency auditing, production builds, and an unpacked-extension guide. Public distribution remains blocked until authentication and abuse controls exist.
